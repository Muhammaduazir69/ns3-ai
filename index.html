ns3-ai-ntn: a Gymnasium 1.0 reinforcement-learning bridge for ns-3

Fork of ns3-ai for ns-3.43: Gymnasium 1.0 over versioned shared memory, an AI-RAN inference contract, and NTN reinforcement-learning tooling.

What ns3-ai does

ns3-ai-ntn is a fork of the ns3-ai module that connects ns-3.43 simulations to Python agents through Gymnasium 1.0 over shared memory, with a versioned handshake that rejects schema mismatches. It adds an AI-RAN inference contract over in-process or TCP channels and a Python package of NTN reinforcement-learning environments and trainers.

What it models

The module is the interface between an ns-3 process and a learning agent rather than a network model. OpenGymInterface on the C++ side is stepped through Notify() each step, and the transition is latched inside GetObservation so the reward is computed from state the action has actually reached. The C++ and Python sides share a protobuf schema over a Boost.Interprocess shared-memory segment; the handshake carries a protocol version, a module version and an FNV-1a schema digest, so a mismatch is reported as an error. Ns3AiMsgInterface exchanges fixed-layout structs and vectors through a pybind11 module. The fork targets Python 3.10 to 3.13, NumPy 2 and Gymnasium 1.0, and a CMake helper disables link-time optimization per pybind11 target to fix the ns-3.43 import failure.

An AI-RAN inference contract (AiranInferenceClient and AiranInferenceServer) exchanges length-prefixed protobuf over in-process FIFO or TCP channels, parses Triton config.pbtxt files, and ships deterministic mock runtimes for a beam index classifier and a CSI-to-precoder model; a native grpc++ transport is not implemented yet. The ns3_ai_ntn Python package provides four NTN environments (HandoverEnv, BeamMgmtEnv, SliceEnv, PowerCtrlEnv), which are synthetic and do not boot ns-3, plus a Stable-Baselines3 PPO trainer, a PyTorch Geometric GAT model and parameter-shared multi-agent wrappers. The environment that runs on a measured radio is OranNtnGymHandover in oran-ntn. Bundled upstream examples cover RL-TCP congestion control, Wi-Fi rate control, LTE CQI prediction and multi-BSS channel access.

Install

Every module ships in the ready-built container image of the toolkit (version 2.7.1):

docker pull uzairdocker69/ns3-ntn-toolkit:latest
docker run --rm -it uzairdocker69/ns3-ntn-toolkit:latest bash

To build from source, clone ns3-ntn-toolkit, which vendors this module under contrib/, or follow the README of this repository (branch fix/ns3-43-compatibility-and-critical-bugs).
